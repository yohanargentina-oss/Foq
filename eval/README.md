# Foq — replayable exam and calibration

Everything here can be rerun on your own machine. Results: [RESULTS.md](RESULTS.md).

## The data

`data/_mega_merged.jsonl`: 2,500 French multiple-choice cases (3 options, 13 categories),
generated by category-specific Python generators. None of them is in the training set of
the production adapter v1 (`data/_external/dataset_avance.jsonl`, 300 items): checked by
exact match and by context near-duplicates (`eval/build_split.py` prints the report).

`eval/build_split.py` splits them in two halves, stratified by category, with the
option order shuffled once and frozen:

| File | Cases | Used for |
|---|---|---|
| `eval/data/calib_val.jsonl` | 1,250 | fitting the temperature, nothing else |
| `eval/data/exam_test.jsonl` | 1,250 | the exam: accuracy, ECE, `needs_review` |

What this exam is, honestly:
- 4 of the 13 categories are business decisions close to Foq's intended use
  (ticket routing, security, sentiment, triage, 325 exam cases); the other 9 are
  counter-intuitive reasoning puzzles (races, spatial, counter-intuitive maths…),
  harder than typical production inputs. Results are reported for both families.
- The cases come from generators, not from real traffic.
- 21 % of the cases were later rejected by the 27B judge when the v2/v3 training set was
  built (it did not recover the expected answer). They are kept: a sample read by hand
  shows correct labels on hard cases, and removing them would flatter the score.

## Replay

```bash
foq setup                                          # weights + adapter
# server without adapter on 8089, with adapter on 8090 (Foq llama.cpp build)
llama-server -m ~/.models/foq/foq-reflex-8b-pq2_0.gguf -ngl 99 -c 4096 -np 1 --port 8089
llama-server -m ~/.models/foq/foq-reflex-8b-pq2_0.gguf --lora adapters/foq_decision_8b/foq_decision_8b.gguf -ngl 99 -c 4096 -np 1 --port 8090

python eval/build_split.py                         # optional: rebuilds the two files; needs data/ (not published)
python eval/run_cases.py --set calib_val --tag bare --base-url http://127.0.0.1:8089
python eval/run_cases.py --set exam_test --tag bare --base-url http://127.0.0.1:8089
python eval/run_cases.py --set calib_val --tag lora --base-url http://127.0.0.1:8090
python eval/run_cases.py --set exam_test --tag lora --base-url http://127.0.0.1:8090
python eval/calibrate.py --tag bare
python eval/calibrate.py --tag lora
python eval/report.py                              # writes RESULTS.md
```

`run_cases.py` prints the exam score with its 95 % confidence interval and stores the raw
log-probabilities of every case in `eval/results/raw_<tag>_<set>.jsonl`. Two runs of the
exam gave the same 1,250 predictions (log-probabilities vary by at most 0.22 between runs
on GPU).

## Calibration method

Temperature scaling (Guo et al., 2017): the letter log-probabilities are divided by T
before the softmax. T minimises the negative log-likelihood on `calib_val` (search bounds
0.02–50; a fit ending on a bound is flagged). ECE uses 15 equal-width bins, with a
bootstrap 95 % interval (1,000 resamples). Accuracy intervals are Wilson intervals.
