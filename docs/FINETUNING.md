# 🎓 LoRA Fine-Tuning of the Decision Adapter (Foq Reflex 8B)

This document describes the complete pipeline to train the **Foq Reflex 8B** into an
even more reliable System 1 decision engine, while keeping the base model intact
(LoRA = a small adapter plugged next to frozen weights).

## Pipeline Overview

```text
┌─────────────────┐   ┌──────────────────┐   ┌────────────────┐   ┌──────────────────┐
│ 1. Calibration  │→ │ 2. Data          │→ │ 3. QLoRA       │→ │ 4. GGUF          │
│ run_calibration │   │ generation       │   │ training       │   │ conversion +     │
│ (8B T*)         │   │ (27B teacher)    │   │ train_lora_8b  │   │ --lora deploy    │
└─────────────────┘   └──────────────────┘   └────────────────┘   └──────────────────┘
```

**Key principle**: the ace 27B (10/10 on traps) acts as the *teacher* — it generates
novel traps, blind-verifies them, and the 8B learns from them (distillation).

## Prerequisites (once)

```bash
# Dedicated training environment (already created in .venv-train):
#   - inherits the system torch (2.5.1+cu121)
#   - pins transformers 4.57 / peft 0.17 / bitsandbytes 0.45 / datasets 3.6
#   (transformers 5.x + torch 2.5 segfault; the datasets->torch->transformers
#    ->bitsandbytes import order is MANDATORY on Windows — see train_lora_8b.py)
py -3 -m venv --system-site-packages .venv-train
.venv-train/Scripts/python -m pip install "transformers==4.57.1" "peft==0.17.0" "bitsandbytes==0.45.3" "datasets==3.6.0" gguf

# 8B training weights (safetensors format, ~16.4 GB):
# unpack the reference weights into %USERPROFILE%\.models\foq\foq-reflex-8b-unpacked\
```

Hardware: an NVIDIA GPU with ≥ 12 GB of **free** VRAM (stop the llama-server
processes during training — they occupy the card).

## Step 1 — 8B-Specific Calibration

```bash
# 8B server running (start_foq_8b_server.cmd), then:
py -3 scripts/run_calibration.py --base-url http://127.0.0.1:8090 \
    --output calibration_profile_8b.json --alias foq-8b
```

Code-side usage: `FoqEngine(base_url="http://127.0.0.1:8090", profile_path="calibration_profile_8b.json")`.

## Step 2 — Dataset Generation

Three complementary sources:

```bash
# a) Parameterized business cases (per-generator quotas, shuffled options,
#    uniform position of the correct answer — anti letter-bias):
py -3 scripts/generate_training_data.py --count-business 4000 --count-riddles 0

# b) Traps generated by an external teacher model (via handoff),
#    then imported with blind verification by the 27B judge:
#    the judge must recover the expected answer, otherwise the item is discarded.
py -3 scripts/import_external_riddles.py <external_jsonl_file> --verify-url http://127.0.0.1:8089

# c) (Optional) Traps generated locally by the 27B teacher:
py -3 scripts/generate_training_data.py --count-riddles 250
```

⚠️ **Anti-contamination rule**: the benchmarks (`precision_benchmark.py`,
`hardcore_benchmark.py`) are **never** used for training. They remain the
untouched exam that measures progress.

Output: `data/lora_dataset.jsonl` (train) + `data/lora_dataset_eval.jsonl` (eval).
Each line: `{"prompt", "target_letter", "domain", "source"}` in the EXACT format of
`DecisionSchema.format_prompt()` (via the real Foq classes — zero format drift).

## Step 3 — QLoRA Training

```bash
# 1. Stop the llama servers (free the VRAM)
# 2. Smoke test (~30 steps) to validate:
.venv-train/Scripts/python scripts/train_lora_8b.py --max-steps 30

# 3. Full training (~15-20 min on an RTX 4080 Super):
.venv-train/Scripts/python scripts/train_lora_8b.py --epochs 2
```

Default settings: LoRA rank 16 (alpha 32, dropout 0.05) on q/k/v/o, 4-bit NF4 base,
lr 1e-4, effective batch 16, loss **only on the letter token** — exactly what
inference reads after the `Réponse : [` priming marker (see
[ARCHITECTURE.md](ARCHITECTURE.md)). Argmax accuracy on the eval set is printed at
the end, per domain.

Output: `adapters/foq_decision_8b/` (PEFT adapter + tokenizer).

## Step 4 — GGUF Conversion and Deployment

The conversion scripts (standalone versions) are already in the repository:
`scripts/convert_lora_to_gguf.py` + `scripts/convert_hf_to_gguf.py` (an interdependent pair).

```bash
# Convert the adapter (with the training venv's Python):
.venv-train/Scripts/python scripts/convert_lora_to_gguf.py adapters/foq_decision_8b \
  --base %USERPROFILE%\.models\foq\foq-reflex-8b-unpacked \
  --outfile adapters/foq_decision_8b/foq_decision_8b.gguf

# Deploy (the base model stays unchanged, the adapter plugs on top):
set LORA_PATH=adapters\foq_decision_8b\foq_decision_8b.gguf
start_foq_8b_server.cmd
```

## Step 5 — Re-Take the Exam

```bash
FOQ_BASE_URL=http://127.0.0.1:8090 py -3 scripts/precision_benchmark.py
FOQ_BASE_URL=http://127.0.0.1:8090 py -3 scripts/hardcore_benchmark.py
py -3 scripts/run_calibration.py --base-url http://127.0.0.1:8090 \
   --output calibration_profile_8b_lora.json --alias foq-8b-lora
```

Goal: keep 29/29 on business cases, gain on traps (9/10 → 10/10), then
**recalibrate** (any weight change invalidates the T* temperature).

## Honest Limitations

- The LoRA corrects **systematic biases** (traps always missed the same way),
  not general intelligence: a never-seen type of trap can still fool the model.
- The adapter is only active with `--lora`: without it, the official 8B is untouched.
- After any weight change, rerun the calibration (step 1) — mandatory.
